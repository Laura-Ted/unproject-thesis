## Shakedown (pilots, under `artifacts/shakedown/`, not campaign results)

The CUDA path had never run before this instance. In order:

1. `push` failed: the clip list is empty since the evening of 2026-09-15 and
   the directory handed to scp was never created → `49ff14c`.
2. The setup's preflight, run through the vast ssh proxy, lost its session
   during the 1.6 GB weights download; the download completed on the host
   anyway. Long remote steps were run under `nohup` from then on.
3. The CPU suite's preflight read `cpu: NVIDIA GeForce RTX 3060` and
   recorded `device: cuda` beside `device_requested: cpu`, because the
   report described the device `auto` would pick. Jobs were right; the
   archived report was not → `2ac0c4b` (with a test-fixture fix that made
   torch unimportable in the test process).
4. The fixture suite could not run: `datasets/fixture/clip.mp4` is generated
   locally and the setup did not make it; generated by hand with the README's
   ffmpeg command, then added to `setup-instance.sh` → `7e7ac5c`.
5. The shakedown jobs recorded `git_dirty: true`: the logs written into the
   checkout were untracked files. The driver's own `run` did the same with
   `campaign-<id>.log` and would have made the preflight refuse the first
   suite → `7e7ac5c`: the log lives in `/root/unproject-campaign/`.
6. `benchmarks/validate-campaign.py`, the handoff's §7 list as a script → `868cd90`.
